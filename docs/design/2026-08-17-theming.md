# pagina theming — integrate anywhere, feel native

Date: 2026-08-17. Status: approved in conversation; executing.

## The problem, precisely

`https://schemati.test/articles` renders with pagina's *own* default dark theme (blue-violet
`--pg-accent: #7c9bff`) and no host chrome at all. Two separate gaps:

1. `config('pagina.layout')` was documented as swappable but schemati never pointed it at its
   own layout, so article pages render inside the package's bare shell — no nav, no footer.
2. pagina's tokens are hardcoded defaults rather than something a host maps to its own design
   system. schemat.io's accent is magenta `#db45f0`; nothing tells pagina that.

## The goal

pagina should drop into any site and look like it belongs there with minimal effort, while
letting a host that cares take over as much as it wants — up to and including typography.
That is a **spectrum**, so the design is layered rather than a boolean.

## The four layers

| Layer | What it does | Default | How a host overrides |
|---|---|---|---|
| **Structure** | Semantic markup + stable class names (`pg-*`, `pge-*`) and `data-pg-*` hooks | always on | n/a — it's the contract |
| **Tokens** | ~20 `--pg-*` custom properties (surfaces, ink, accent, line, radius, fonts) | on, with neutral defaults | redefine any subset in one place |
| **Reading** | Content-column craft: measure, heading rhythm, code, admonitions, tabs, tables, figures | on | override rules, or drop the layer |
| **Chrome** | Header, sidebar, TOC, pager, theme toggle | on for the standalone site; **off** when a host supplies its own | host layout + slots |

### Mechanism: CSS cascade layers

`pagina.css` wraps everything in `@layer pagina.reset, pagina.tokens, pagina.reading, pagina.chrome;`.
Unlayered CSS always beats layered CSS regardless of specificity, so **any host rule wins by
default** — a host restyles `.pg-content h2` with a plain selector and no `!important`. Hosts that
want a *partial* override get it for free; hosts that want none do nothing.

This is the same asymmetry that bit us on MkDocs earlier: layered loses to unlayered. Here we
want to lose, so we take the layer.

Escape hatches, in increasing order of control:
1. **Map tokens** (most hosts stop here) — a ~20-line file mapping the host's variables to `--pg-*`.
2. **Override rules** — ordinary CSS; wins automatically thanks to the layers.
3. **`theme: "tokens"`** — the shell emits structure + tokens and skips the reading layer entirely,
   for hosts that want to style the content column themselves.
4. **`theme: "none"`** — no pagina CSS at all; structure only.

### Token contract (the published surface)

```
--pg-bg  --pg-bg-raised  --pg-bg-sunken      surfaces
--pg-fg  --pg-muted                          ink
--pg-accent  --pg-accent-fg                  primary action / links
--pg-line  --pg-line-strong                  rules and borders
--pg-radius  --pg-radius-lg                  corner rhythm
--pg-font  --pg-font-mono  --pg-font-display type
--pg-measure                                 content column width (default 72ch)
--pg-note --pg-tip --pg-warning --pg-danger  admonition hues
--pg-code-bg  --pg-shiki-bg                  code surfaces
```
Every one is defined as `var(--pg-x, <neutral default>)`, so a host maps by *defining the token*,
never by editing pagina. The editor's `--pge-*` set keeps only genuinely tool-specific values
(pane widths, split) and inherits everything else from `--pg-*` — one contract, two surfaces.

### Chrome and slots (Laravel)

`config('pagina.layout')` gets wired for real: the package's Livewire pages render inside the host
layout, and the shell drops its own header when the host provides chrome (`pagina.chrome => false`).
Named slots — `pagina::actions`, `pagina::sidebar-top`, `pagina::footer` — let a host inject its
own controls without forking a view.

## Reference implementation: schemat.io

A ~20-line `resources/css/pagina-theme.css` maps Tailwind/Flux variables (`--color-accent`,
surface greys, the app font) onto `--pg-*`; `pagina.layout` points at
`components.layouts.app`; `pagina.chrome` is false so the app's nav is the only nav; the
"Articles" nav item highlights on article routes. Nothing in pagina knows schemat.io exists.

## Testing

- Token contract: a test asserts every documented token is consumed and has a default.
- Layer order: a test asserts the emitted CSS declares `@layer pagina.…` first and that an
  unlayered rule beats a pagina rule (jsdom + `getComputedStyle`).
- `theme: "tokens"` / `"none"` emit the expected subsets.
- Laravel: the rendered page contains the host layout's markers and not pagina's header when
  `chrome => false`.
- Visual: the schemat.io articles index and a published article, before/after, in the browser.
