# Social cards — design

Date: 2026-08-19. Status: approved by the user's brief, incorporating the Kineglyph side's proposal
(glyph slot vs full-scene card, embedded fonts, build-time only).

## Where this starts

`og:image` is `page.cover ?? article.cover`. An article with no cover emits **no** `og:image` and no
`twitter:image`, and the Twitter card degrades from `summary_large_image` to `summary` — the small,
imageless one. So a page nobody drew a cover for shares as a bare text link, which is most pages.

What makes this cheap: `@kineglyph/export` already exports `exportPng`, backed by `@resvg/resvg-js`
with harfbuzz text shaping. pagina already depends on it, and all thirteen resvg platform binaries are
already in the lockfile. Scene → SVG → PNG, in Node, no browser.

## Three ways to get a card, in order of precedence

1. **An author's image.** `cover:` (or `og.image:`) wins. Someone who drew a card gets their card.
2. **A composed card.** pagina lays out title, description, site name and accent, and may place a
   **glyph** — a Kineglyph scene — in a slot within that composition.
3. **A procedural card.** No glyph, no cover: a deterministic mark derived from the article slug, so
   every page still shares as something rather than nothing, and the same page always looks the same.

3 is the floor, not the aspiration. It exists so the answer to "what does this page share as" is never
"nothing", and it must look deliberate rather than like a placeholder.

## The glyph slot

pagina owns typography and composition; Kineglyph owns the illustration. That division is the whole
point — a card is editorial, and a diagram is data.

```yaml
og:
  template: editorial          # which composition
  glyph: scenes/architecture.mjs
  glyph_position: right        # where the slot sits
  glyph_width: 520
  time: end                    # a static frame of a timeline
```

Per-page front matter overrides the article, the same way `cover` and `theme` already do. A page may
also say `og: false` to opt out entirely.

**Full-scene cards** — the whole 1200×630 as one Kineglyph composition — fall out of the same
mechanism: a template whose slot is the entire canvas. Worth supporting, not worth a second code path.

## Decisions

**Baked, not inherited.** Figures resolve colour at view time through `var(--kg-color-*)`. A card
cannot: a crawler fetches a PNG with no page, no CSS and no theme. So the card's palette is **resolved
at generation time** from whichever theme level applies. Same tokens, opposite binding time, and the
reason is the consumer rather than the content.

**Fonts are embedded, and system fonts are off.** `loadSystemFonts: false` with explicit font files.
A card generated in CI must be byte-identical to one generated on a laptop; a system font makes that
untrue and the difference only shows up months later as a card nobody can reproduce.

**Cached by everything that can change it.** Title, description, theme, template, glyph source,
dimensions and font files all feed the key. A build that changes no card should rewrite no PNG.

**A broken glyph must not fail the build.** A scene that throws falls back to the composed card
without it, and reports a diagnostic. One bad figure taking down a docs deploy is a worse failure
than one plain card.

**Build time only.** resvg is Node, not an edge runtime. Cards are generated during the build and
served as files. That is the right architecture anyway: a social crawler wants a URL that responds
immediately, not one that renders on demand.

**`twitter:image:alt` comes from the card's own content** — the title and description it was drawn
from — with an override. An image with no alt text is the accessibility gap that social cards
reliably ship.

## Not now, but the shape allows it

Per-page glyphs driven by page data (`defineOgCard({ glyph: overview(page.data) })`), named timeline
cues instead of a raw `time`, and templates supplied by the host rather than chosen from pagina's set.
None of these need the format to change; they need the resolver to accept a function where it
currently accepts a path.

## Verification

A card is a picture, so the bar is a person looking at it — but the parts that rot silently are
mechanical, and those get tests: precedence (author image beats composed beats procedural), the
procedural mark being stable for a slug, the cache key changing when each input changes, a throwing
scene degrading rather than failing, `og:image` and `twitter:image` pointing at a file that exists,
and the emitted card being 1200×630. Then look at ten of them.
